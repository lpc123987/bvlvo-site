# BVLVO WORLD 代币机制设计 V0.1

2026-09-06｜讨论与仿真方案｜未发行、未部署、未开放销售

## 1. 定位

BVLVO 的潜在用途：让独立参与者共同出资采购有价值的实验、复现和场景维护，并参与公共研究预算的有限治理。它不代表公司股权、收益分红、客户授权或质量认证。

核心问题：真实的测试需求，能否支持一个持续生产有效场景的网络？只有多个独立服务方确实需要共享结算和协调，才进一步考虑可交易代币。普通支付必须保留。若数据库和普通资金足以满足需求，应保留非代币方案。

## 2. 三本账：额度、贡献、代币

| 对象 | 用途 | 转让与边界 |
|---|---|---|
| 测试额度 Credits | 按实际成本报价的测试服务 | 站内不可交易；不与币固定兑换；退款规则单独确定 |
| 贡献记录 Reputation | 场景作者、独立复现、纠错与维护记录 | 不出售、不转让；可申诉纠正；按领域展示，避免单一总分 |
| BVLVO | 未来可能的公共实验预算协调与可选结算 | 当前仅模拟；不能购买人的权限、测试通过结果或贡献声誉 |

现有经济实验台中的“模拟记账单位”与以上三者完全隔离。不得把模拟交易量称为网络收入或代币需求。

## 3. 首要机制：先有实验预算，再奖励证据

1. 企业或研究者提出测试问题，明确场景范围、验收条件和预算。
2. 场景贡献者提交可执行场景、权限来源及复现说明。
3. 不同参与者独立复现，审核现实相关性、重复性与是否泄露数据。
4. 客户验收，按预先约定分配预算。争议部分保留，非争议服务按约结算。
5. 后续客户确实购买该场景使用服务时，可依合同向维护者支付维护报酬；无永久版税保证。

不得按照提交数量、代理数量、调用次数或自买自卖的交易额直接增发奖励。

初期由人工审批，记录利益冲突；场景作者不能单独批准自己的奖励。复现工作即使否定场景也应获得事先约定的基础报酬，避免“必须成功才能拿钱”的偏差。

## 4. 钱从哪里来

现金收入来自付费测试、私有实验与维护服务；启动资金必须是明确可用的运营预算。尚未出售的自有代币不记为可支付云服务账单的现金。

每笔订单：可分配余额 = 已结算收入 − 税费与支付成本 − 计算成本 − 已承诺交付与审核成本 − 合同所需退款准备。余额为负则不发可选奖励，应改价、限额或停止该类订单；不能通过发更多币填补现金亏损。

仅用于说明的算例：收到100单位资金；交付、计算和核验60；其他费用与退款准备10；剩余30。其中12用于场景贡献报酬、6用于公共复现预算、12用于运营。实际比例必须经成本测量后确定。准备金不等于收入，也不能提前分完。

若以后支持 BVLVO 支付，报价应以实际成本计价，有短时有效期并明确谁承担价格波动；不得承诺“1币永久等于固定算力”。需先解决市场流动性、报价操纵、托管、退款和专业合规评估。普通支付是基线。

## 5. 供应与分配：先在仿真里比较

以下是测试参数，不是正式代币发行方案。使用1,000,000个无现金价值的测试单位，便于观察预算消耗。真实总量、链、精度、初始流通量和销售安排均未决定；早期提及 Solana 不构成链的最终选择。

| 测试预算池 | 比例 | 测试单位 | 拟议用途 |
|---|---:|---:|---|
| 有效贡献 | 40% | 400,000 | 经验证的场景、复现和维护 |
| 公共实验 | 20% | 200,000 | 公开基准、反例挑战与重复研究 |
| 运营储备 | 20% | 200,000 | 可核查的基础设施和持续维护预算 |
| 核心建设者 | 15% | 150,000 | 模拟长期建设激励 |
| 外部集成 | 5% | 50,000 | 已验收的接口和接入工作 |
| 合计 | 100% | 1,000,000 | 无预售、无交易市场、无真实分配 |

仿真中核心建设者池先锁定12个月，随后36个月等额解锁，用来测量集中度和解锁压力；并不自动约束或授予任何人的现实权益。其余池根据已批准工作释放，不按日历全部发完。未使用留存，测试期不增发。所有转移追踪去向和重复收款关系。

固定总量只是实验选项，不证明长期可持续。应对照普通预算方案；启动补贴减少后若没有真实收入支撑，机制视为未通过验证。

## 6. 治理：代币不能决定真相

可讨论事项：公共实验预算、拟新增场景领域、协议升级优先级。

不可由持币多数覆盖：用户授权、数据隐私、订单已约定条款、核验结果、他人资金与申诉权。

初期采用公开提案、实名或经核查的项目参与者审查、运营方明确负责的执行模式，不冒称去中心化。持币意见与独立贡献者审查分别展示；技术正确性不能靠币数投票。测试中比较持币投票与贡献审查对预算集中的影响。

如未来实施链上财库，拟采用多方签署、变更延迟、权限披露与独立安全审查；具体签署人、阈值、管理员权限需另行确定。一个地址一票和平方根投票都不能独自阻止拆分账户。

## 7. 滥用与经济压力测试

| 情况 | 处理与验收 |
|---|---|
| 批量无效场景 | 限速、去重、人工初审；允许低成本参与，不简单按财富准入 |
| 作者与核验者串通 | 利益披露、随机复核、隐蔽对照任务；争议由不同人员复审 |
| 场景只对特定模型有效 | 明确模型和版本；检查多个配置，不虚称普遍缺陷 |
| 自买自卖刷奖励 | 排除关联交易、设置预算上限、按净外部需求核验；身份识别仍有成本和误判 |
| 奖励大于收入 | 显式补贴账与余额约束；余额不足停止新增奖励 |
| 币价跌80%或流动性消失 | 现金运营账隔离；可选币支付暂停，已承诺订单按合同处理 |
| 最大贡献者退出 | 版本可重放、维护交接、经许可的场景可移植 |
| 持币集中 | 披露最终受益关联；公共预算独立审查；不宣称可完全消除控制风险 |

不设置固定年化、持币分红、保底回购或交易税。也不把自动销毁当作价值来源。可选反垃圾保证机制应先采用额度和限速；目前不引入自动罚没真实资产。

## 9. 进入真实代币阶段的门槛

需要同时具备：持续的外部付费需求；清楚的交付成本；多个独立参与方的协调需求；普通数据库方案不足的证据；反作弊与申诉流程；对运营所在地和拟服务地区的专业法律评估；明确的主体、权利、税务和财务处理；代码和权限安全审查。

未满足门槛时继续使用普通支付和不可交易额度。原型积分不承诺兑换未来代币，不承诺空投。没有任何研究成果自动使代币具有投资价值。
