# BVLVO WORLD：每周迭代计划

版本：V0.1 / 2026-09-06。本文是开发计划，不是已完成能力或发布日期承诺。

## 产品假设
让智能体开发者在相同需求、资源与冲击下比较规则，发现协作系统的失败条件。第一版为确定性规则模拟器，不调用大模型，不代表真实市场，也不发行代币。

## 每周工作节奏
- 第1天：回顾上周证据，只选择一个主要问题，冻结验收条件。
- 第2—3天：实现最小实验，保留上一版与固定基准场景。
- 第4天：检查计算、边界、可复现性和手机操作。
- 第5天：演示给用户，记录困惑和发现；决定保留、修改或停止。
- 每次版本记录：假设、改动、实验参数、结果、限制、下一周决策。无需为了赶周更上线未验证的功能。

## 八周路线
| 周次 | 研究问题 | 交付 | 验收与决策 |
|---|---|---|---|
| W1 / V0.1 | 不同分配规则能否呈现可解释的差异？ | 三规则、三场景、相同种子、逐轮记录与结果导出 | 固定输入结果一致；资金与容量不越界；每个指标能解释；用户能说出一项规则取舍 |
| W2 / V0.2 | 这些差异能被别人重现吗？ | 导入实验、版本号、固定场景集、计算核对报告 | 导出再导入结果一致；极端容量和预算案例通过 |
| W3 / V0.3 | 故障如何传播？ | 延迟、重试与重复订单；因果回放 | 至少发现并复现一种失败；修复后相同案例不再失败 |
| W4 / V0.4 | 人的授权能在任务转交后生效吗？ | 预算授权、撤销、子任务权限、越权拦截 | 撤销后禁止新操作；子任务权限不得超出父权限 |
| W5 / V0.5 | 模型行为相对规则代理带来什么变化？ | 接入一种真实模型，限制工具与费用；保留规则基线 | 明确区分模型输出与规则脚本；记录费用；重复试验展示波动；先由用户授权成本 |
| W6 / V0.6 | 人贡献的异常场景是否有增量价值？ | 场景提交、去重、复现与人工审核 | 一项新场景发现基准集未覆盖的失败；不用上传数量作为价值指标 |
| W7 / V0.7 | 外部开发者能否独立使用？ | 私有实验、简单接入说明、试用访谈 | 至少邀请3位目标用户；记录完成率与实际问题；没有需求则缩小或改变定位 |
| W8 / V0.8 | 是否值得持续投入？ | 总结报告、下一周期路线与成本记录 | 按发现问题的价值、维护成本和继续使用意愿判断；不以代币关注度替代需求 |

## V0.1 模型定义
20位程序化买家，5家供应商，7轮交易。每轮每位买家最多购买1单位。买家有固定初始预算和最高接受价格，供应商有固定报价与每轮容量。每次比较使用相同种子生成同一批参与者。

规则A：按最高接受价格从高到低安排买家，选择报价最低且满足预算/容量的供应商。
规则B：优先累计成交少的买家，平局按轮次循环排列；供应商选择仍为最低报价。
规则C：优先累计成交少的买家，并优先分配给累计成交少的可用供应商。它是分散采购，不提供故障保险或保证恢复。

场景：正常；第4轮起最低报价供应商离线；第4轮起所有供应商容量减半并向下取整。报价固定，没有议价、串谋、学习、物流或真实AI。模型只用来理解机制，不证明哪条规则在现实最优。

指标：成交率=成功单位/140；支出=成交价格总和；买家服务差距=最高与最低累计成交量之差；供应集中度HHI=各供应商成交量份额平方和，零成交时不计算；冲击后成交率=第4—7轮成功单位/80。所有轮次独立需求，未成交需求不积压。

## 发布边界
第一版在本地预览，与现有官网分开。上线替换属于用户此前保留本人确认的关键步骤。演示不连接钱包、不收款、不发行代币、不把模型内单位标为现实货币。

## 长期方向
公开可重现的实验与场景；在需求验证后考虑私有测试与持续检测服务。代币必要性单独研究，不作为前八周的交付目标。本计划不创建自动周更或自动发布任务。
